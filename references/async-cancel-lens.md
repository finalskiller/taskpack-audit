# 异步取消语义镜头

> 只有当题面确实是「可取消的异步任务」时用这个镜头。其它题族换成等价的状态 × 事件矩阵。
> 这是**提问清单**，不是题面要求。每条都要回 `instruction.md` 找依据；找不到就进 `U*`。

## 1. 先把状态和事件列全

状态：

| 状态 | 含义 | 可观察 |
|---|---|---|
| `pending` | 已提交，协程还没开始 | `state`、`steps == 0` |
| `running` | 正在执行，停在某个 await | `state`、`steps` 增长 |
| `cancelling` | 已请求取消，尚未落到取消点 | `cancel()` 返回值、`state` |
| `cancelled` | 取消完成 | `state`、`await` 抛 `CancelledError` |
| `done` | 自然结束 | `state`、返回值 |
| `failed` | 任务体抛异常 | `state`、异常类型 |

事件：

`submit` / `cancel()` / 第二次 `cancel()` / `await handle` / 任务自然完成 / 任务体抛异常 / `run_all()` / 进程退出。

## 2. 状态 × 事件矩阵（逐格问「题面要求什么」）

| 状态 \ 事件 | `cancel()` | 第二次 `cancel()` | `await` | 自然完成 | 抛异常 |
|---|---|---|---|---|---|
| pending | 返回？协程体是否允许执行？ | 返回？ | 抛什么？ | — | — |
| running | 返回？停在哪个检查点？ | 返回？ | 抛什么？ | — | — |
| cancelling | 重入是否安全？ | 返回？ | 抛什么？ | — | — |
| cancelled | 返回？ | 返回？ | 抛什么？ | — | — |
| done | 返回？是否抛？ | 返回？ | 返回值？ | — | — |
| failed | 返回？ | 返回？ | 原异常还是 CancelledError？ | — | — |

每一格三问：
1. 题面要求这里发生什么？（找不到 → `U*`）
2. 现在哪条测试管它？（找不到 → `missing_validation` 候选）
3. 那条测试的断言能不能区分「做到」和「没做到」？（不能 → `wrong_validation` 候选）

## 3. 可观察信号清单

- `cancel()` 的返回值（True/False）。
- `await handle` 抛出的异常类型。
- `handle.state` 的终态。
- `handle.steps`：取消后是否停止增长；停在第几步。
- 任务体里 `finally` / `cleanup` 是否执行。
- 其它任务的 `steps` / `state` 是否受影响。
- 任务体的日志/副作用（文件、队列、计数器）。
- 时序：取消到停止的耗时（**只作辅助信号，不要单独作为断言**）。

## 3.5 run_all 与进程退出

矩阵之外还有一组容易漏的可观察量：

- `run_all()` 是否等待**全部**任务结束？
- 返回顺序是否等于**提交顺序**？
- 某个任务被取消/抛异常时，`run_all` 是抛、跳过还是收集异常？
- 进程退出时还有未完成任务吗？有没有「daemon task 被回收」的痕迹？
- 取消 `run_all()` 本身怎么处理？（题面没写 → `U*`）

R6 这类要求没有对应测试时，账本里写「无」，不要因为「R6 已映射到某个取消用例」就算覆盖。

## 4. 变异体（每个先写「目标可观察量」和「哪条测试应该杀死它」）

**一个变异体只改一个行为。** 改两个，存活了也说不清漏洞在哪。

| ID | 单点变异（只改这一处） | 目标可观察量 | 应该杀死它的测试 | 存活说明 |
|---|---|---|---|---|
| M1 | `cancel()` 只置状态，不打断；任务体跑完后再抛 `CancelledError` | 取消后 `steps` 是否停止 | 取消执行中的用例 | 只查异常类型，不查 `steps` |
| M1a | 同上，但跑完后**不抛**异常 | `await` 是否抛错 | 异常类型用例 | 异常断言有效；但 M1 仍存活 |
| M2 | 取消后仍多执行一步再抛 | 取消点后的 `steps` | 检查取消点的用例 | 取消点没卡准 |
| M3 | 第二次 `cancel()` 抛异常 | 第二次调用的返回值/异常 | 幂等用例 | 幂等没测 |
| M4 | 取消**已完成**任务返回 True | `cancel()` 返回值 | done 后返回值用例 | 返回值没测 |
| M5 | 吞掉 `CancelledError`，正常返回 | `await` 是否抛错 / 状态 | 异常传播用例 | 只测「不抛」没测「停了」 |
| M6 | 取消 A 时把 B 也取消 | B 的 `steps` / `state` | 隔离用例 | 并发隔离没测 |
| M7 | 跳过 `finally` / 清理 | `cleanup` 标志/副作用 | 清理用例 | 清理没测 |
| M8 | `await` 后 `cancelled()` 为 False，或不抛错 | 终态 + 异常 | 终态用例 | 终态没测 |
| M9 | pending 取消仍执行协程体 | `steps == 0` | 「一步都不执行」用例 | 只查异常没查 `steps` |
| M10 | 对已完成任务 `cancel()` 抛异常 | 是否抛异常 | done 后不抛用例 | 同 M4，测的是异常面 |
| M11 | pending 取消返回 False | `cancel()` 返回值 | pending 返回值用例 | 返回值没测 |
| M12 | running 取消返回 False | `cancel()` 返回值 | running 返回值用例 | 返回值没测 |
| M13 | `run_all()` 返回顺序反转 | 返回列表顺序 | 顺序用例 | R6 没测 |
| M14 | `run_all()` 不等待全部，或吞掉异常 | 是否全部结束/异常 | run_all 用例 | R6 没测 |

写变异体的最小做法：复制参考实现，改一个行为，跑测试，记录「哪条挂 / 哪条没挂」。没挂的对应 R 就是漏洞。

**观测通道**：用 pytest / 包自带 runner 的退出码和失败用例名；不要用 `test.sh` 的 reward（可能恒 1）。

## 5. 题面常见未定义项（先查，别急着判测试）

- 取消后 `await` 抛 `CancelledError` 还是返回 `None`？
- 取消 pending 任务，协程体是否允许执行？
- 第二次 `cancel()` 返回 `False` 还是抛异常？
- 取消已完成任务返回 `False` 还是抛异常？
- `result` 在取消后是什么？
- 日志/异常消息有没有规定？
- 取消 `run_all()` 本身怎么处理？
- 在任务体内部调用 `cancel()` 自己，允许吗？
- `finally` 里再 `await` 允许吗？

题面没写的，进 `U*`。测试按某个假设验证时：题面**明确写「未规定」** → `false_rejection`；题面**沉默** → `undefined_requirement`。

## 6. rubric 在这个题族上的锚点

合格条目应该长这样：

| 能力 | 可观察锚点 | 不合格写法 |
|---|---|---|
| 取消 pending 不执行 | `steps == 0` + `await` 抛 `CancelledError` | 「取消成功」 |
| 取消 running 停止 | 取消后 `steps` 不再增长，且 < 总步数 | 「任务停止」 |
| 清理执行 | `cleanup is True` / `finally` 里的副作用 | 「资源释放」 |
| 幂等 | 两次 `cancel()` 返回值 `[True, False]` | 「重复取消不出错」 |
| 隔离 | B 的 `steps` 继续增长、`state == "done"` | 「互不影响」 |
| 返回值 | done 后 `cancel() is False` | 「返回值正确」 |

写 rubric issue 时，把「题面哪条 R + 可观察锚点」一起写进 evidence，标注员才判得了。
