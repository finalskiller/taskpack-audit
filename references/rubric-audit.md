# rubric 审计：三仿真 + 四算术

> 不要当散文读。把 rubric 当成一个函数：输入是提交，输出是分数。函数有 bug，就用不同输入试出来。

## 仿真一：参考解（必做）

**对象不是 `solve.sh` 本身。** `solve.sh` 往往只是安装动作；要找它执行后写出的实现。

1. 先解析 `task.toml`：`[solution].reference`、`[verification].entry_impl`、`[solution].entry`。
2. 执行 `solve.sh`，确认产物落在哪；在 `work/env.md` 记一行「参考解产物 = 文件:行，来源 = …」。
3. 把该产物当提交，逐条打分。**先确认 solve.sh 产物 = tests 实际加载的产物**；不是同一个文件，先记 `tooling_defect`，参考解仿真只对 tests 加载的那个文件打分。

| # | 条目 | 判据/锚点 | 参考解证据（文件:行 / 运行输出） | 得分 | 判定 |
|---|---|---|---|---|---|
| 1 | 取消后状态 cancelled | `state == "cancelled"` | runner.py:88 | 20/20 | 满足 |
| 4 | 必须用 TaskGroup | 代码含 `TaskGroup` | runner.py:41 用 `create_task` | 0/15 | 不满足 |
| 5 | 所有测试通过 | reward=1 | test.sh 无条件写 1；真实 pytest 未跑 | 20/20 | 不可信，转仿真二 |

判定四种：**满足 / 部分 / 不满足 / 不可判（信息不足）**。不可判要写缺什么信息：缺运行输出 → `unobservable`；缺锚点 → `undefined_criterion`。不要用「大概满足」糊过去，也不许估分。需要运行才能判的条目（测试通过、性能、日志），证据列写「命令 + 关键输出」，不要硬填文件行号。

- 不满足 → 先去 `instruction.md` / `README.md` / `task.toml` 找裁判：
  - 题面要求了，参考解没做到 → 可能是参考解 bug，写进 notes，不硬判 rubric。
  - 题面没要求，rubric 要求了 → `contradicts_code`，impact 写「参考解被扣 X 分」。
  - 题面允许另一种实现，rubric 只认这一种 → `penalizes_correct`。
- 部分 → 看档位是否可判；判不了 → `undefined_criterion`。

**关键**：参考解不是标准答案，是对照组。rubric 与它冲突，先查题面，再判谁错。

**类型优先级**：参考解掉分时先查题面——题面没要求 → `contradicts_code`；题面允许但 rubric 只认一种 → `penalizes_correct`；纯算术/档位 → `process_defect`。不要同一处写两条。

## 仿真二：坏解（必做，至少 2 个）

构造「看起来对、实际错」的实现，按 rubric 打分。坏解拿高分 = rubric 在奖励错误做法。

四个原型，至少覆盖前两个：

| 原型 | 做法 | 应该拿多少分 | 如果拿高了说明 |
|---|---|---|---|
| 空解 / 测试入口欺骗 | 交空实现，或只让 `test.sh` 写出 reward 1 | 低；条目 5 应为 0 | 条目看 reward/测试通过，不看能力 |
| 只做表面功夫 | 只置状态/只返回 True，不产生副作用 | 低 | 条目只看代理信号 |
| 钻测试空子 | 针对测试断言硬编码，不实现能力 | 低 | 条目奖励「测试通过」而不是能力 |
| 功能对但风格差 | 行为正确，命名/结构不合口味 | 高 | 风格条目在惩罚正确实现 |

**P4 → P5 交接**：至少一个坏解必须是 P4 存活的变异体（例如「cancel 只置标志、不打断执行」）。同一个变异体既记测试结果，也记 rubric 得分。这样「测试全绿」和「rubric 高分」才能对上是同一个错误实现。

打分表：

| 坏解 | 条目 1 | 条目 2 | … | 总分 | 判定 |
|---|---|---|---|---|---|
| B1 只置标志（P4 M1 存活） | 20 | 20 | … | 70 | `rewards_wrong_behavior` |

**阈值**：不看总分，看条目——**任一坏解在一条「不要求题面能力」的条目（测试通过率、行数、库名、日志文案、风格）上拿满分，直接写 issue**。总分 ≥ 60% 只作辅助信号；因为无锚点条目的主观分会让总分在 40–60 之间摆动。

## 仿真三：双标注员（有时间就做，别用单 agent 冒充）

目的：测「两个标注员会不会打出不同的分」。**答题与评分必须分离**（Nuwa 保真评分卡的同一条铁律）。

### 提交包

```
work/labelers/submission/
├─ impl/                被测实现（全量文件或 diff）
├─ run_log.txt          真实 pytest 汇总行 + reward.txt 内容
└─ files.md             文件清单
```

标注员只拿 `rubric.md` + 这个 submission 目录；不给包路径、不给 instruction、不给设计者笔记。

### 执行

1. 把 `rubric.md` + `submission/` 各复制到 `work/labelers/A/`、`work/labelers/B/`。
2. 两个独立 agent，prompt 里明确「不得读 A/B 目录以外任何文件」。
3. 各打两份输入：参考解、一个坏解。只打一份，测不出「坏解识别」。
4. 输出 `{item: score, total, reason}`。

### 分差与裁决

- 条目分差 ≥ 1 分且 ≥ 条目分值的 20%，或总分差 ≥ 10 分 → 进入复核。
- 复核先看是不是某一方误读代码/漏看文件：能解释成标注员误差的，记「标注员误差」，**不进 issue**。
- 解释不了的才归：判据没有锚点 → `undefined_criterion`；标注员拿不到信息 → `unobservable`；两人对题面理解不同 → 先查 instruction，可能是 `contradicts_code`。

### 没有 subagent

同一 agent 分两段、中间清空上下文重贴 rubric + 提交，只能算「未双盲」，写进 notes；**不能拿它作为 `unobservable` / `undefined_criterion` 的证据**。

## 四算术（5 分钟，必做）

1. **加总**：输出三个数——`Σ条目`、rubric 声称满分、`task.toml [rubric].max_score`。三者不等 → `process_defect`，并注明哪个来源不一致。
2. **上限**：单条分值是否超过总分？扣分是否可能为负？档位换算是否闭合？
3. **分布**：核心 R 条目 vs 代理/风格/测试通过条目的分值排序；次要项分值 ≥ 核心项 → 可能 `process_defect` 或 `rewards_wrong_behavior`。条目 1 一句判据塞三个条件却只有一个总分、没有部分分规则，也记在这里。
4. **重复**：两条的锚点并排，是否指向同一个可观察量？是否存在**汇总型条目**（测试全过/覆盖率/总分达标）覆盖了其它条目的行为？有则 `duplicate_scoring`，并算「重复给分总额」。

**通道检查**：rubric 的 100 分怎么变成 `reward.txt` 的 0/1？若 task.toml 只消费 reward.txt、rubric 不参与机器评分，写 `process_defect`（评分流程不可执行），不要让标注员以为 rubric 会影响 reward。

## 要求覆盖（与 P3 共用 R 表）

| R | 题面要求 | 对应条目 | 锚点 | 判定 |
|---|---|---|---|---|
| R3 | 取消后不得再执行任务体 | 条目 2「取消生效」 | 只写 `state == cancelled` | 无锚点 → `missing_criterion` 或 `undefined_criterion` |
| R4 | 二次 cancel 返回 False | 无 | — | `missing_criterion` |

「完全没有条目」→ `missing_criterion`；「有条目但没锚点」→ `undefined_criterion`。两者可以同时出现在同一行：一条说「缺条目」，一条说「现有条目不可判」，但**改法要合并成一句**，不要拆两条凑数。

**汇总型条目不算覆盖锚点**：条目 5「所有测试通过」、覆盖率、总分达标这类，不能拿来证明 R2–R9 被覆盖；它们只说明「测试通道」，不说明「行为被验证」。用汇总型条目做锚点的，直接判 `missing_criterion`。

## 常见误判

- **把「参考解没做到」当成 rubric 错**：先去题面找依据；题面要求了就是参考解的问题。
- **把「条目太细」当成重复计分**：两条看不同可观察量，不算重复。
- **把「风格条目」一律判死**：有锚点、有规则、参考解能满分的风格条目是合法的；只有无锚点/惩罚正确实现才是问题。
- **只做参考解仿真**：坏解仿真才能抓「奖励错误做法」，这是 rubric 审计的一半。
- **用单 agent 自评冒充双标注员**：只能写「未双盲」，不能作为 unobservable 的证据。
