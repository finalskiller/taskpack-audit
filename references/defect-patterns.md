# 缺陷模式库

> 用法：P3/P5 逐函数、逐条目过一遍。命中不是结论，是候选；每条都要用「怎么证明」那一列去证实。
> 模式是提示，不是判据。判据在 `issue-taxonomy.md`。
>
> **编号警告**：本文件的 `T01–T24` / `R01–R18` 是**模式编号**，不是 `review.json` 的 issue id。
> 提交时 issue id 从 `T01` / `R01` 重新连续编号，不要照抄模式编号。

## 测试侧（24 条）

| ID | 模式 | 触发信号 | 怎么证明 |
|---|---|---|---|
| T01 | 只查状态不查副作用 | 断言 `state` / `cancelled()` / 标志位，不断言步骤数、执行痕迹 | 写「只置标志不打断」的变异体，跑测试；仍过即命中 |
| T02 | 只查异常类型 | `pytest.raises(X)` 之后没有其他断言 | 写「跑完全部步骤再抛 X」的实现；仍过即命中 |
| T03 | 空实现也能过 | 断言只查 `is not None` / 长度 >0 / 文件存在 | 把被测函数换成 `pass` / 返回占位值；仍过即命中 |
| T04 | 断言 mock 而非被测代码 | `assert mock.called` / `mock.return_value` 是唯一断言 | 去掉被测代码、只留 mock；测试仍过即命中 |
| T05 | 期望值来自被测实现 | 期望值调用同一个函数算出，或从实现里复制 | 改实现的一个常量；测试跟着变/照样过即命中 |
| T06 | 只测 happy path | 没有空输入、无任务、异常、重复调用、并发用例 | 对照契约表，逐条 R 找「违反它的实现会不会挂」 |
| T07 | 边界值缺失 | 只测 0/1，没测空、单个、上限、负数、None | 列边界表，逐格问「哪条断言覆盖」 |
| T08 | 时序竞态 | `sleep` 后 cancel、墙钟阈值、无 Event/Barrier | 连跑 50 次或加负载；没翻转也可按静态判据写，注明「本地未复现」 |
| T09 | 过度断言实现细节 | 精确文案、内部属性名、调用次数、异常消息 | 构造功能等价但文案/结构不同的实现；挂即命中 |
| T10 | 吞异常 / skip / xfail | `try/except: pass`、`assert True`、`@pytest.mark.skip` | 把关键用例改成必失败；测试仍绿即命中 |
| T11 | 共享状态 / 顺序依赖 | 模块级变量、单例、未清理的全局 task | 单独跑 vs 一起跑；结果不同即命中 |
| T12 | 测试自己做了被测的事 | fixture 里直接构造结果，断言 fixture | 删掉被测调用；测试仍过即命中 |
| T13 | 只测返回不测副作用 | 断言返回值，不断言文件/计数/清理/状态迁移 | 写「返回对但副作用没做」的实现；仍过即命中 |
| T14 | 没有 await 完成 | cancel 后立刻断言，没 await / 没等事件 | 把调度改成延迟执行；断言仍过即命中 |
| T15 | 超时缺失 | 被测可能挂死，测试没 timeout | 写一个死循环实现；测试挂住即命中 |
| T16 | 环境依赖 | 网络、GPU、时区、locale、绝对路径、端口 | 断网/改时区/换目录跑；挂即命中 |
| T17 | 断言过宽 | `in`、`>=`、`is not None`、只查前缀 | 构造「刚好满足宽断言但语义错」的值；过即命中 |
| T18 | 不测并发隔离 | 只测单任务，或把 A、B 都取消再断言 | 写「取消 A 波及 B」的实现；过即命中 |
| T19 | 清理 / finally 未验证 | 只测「取消成功」，不测 cleanup 标志/文件/句柄 | 写「跳过 finally」的实现；过即命中 |
| T20 | reward / 退出码缺陷 | `|| true`、`set +e`、无条件写 reward、pytest 退出码没传 | 故意让测试挂，看 reward 是否仍为 1 |
| T21 | 断言日志文案 | `log == [...]`、`stdout == "..."`，题面没规定文案 | 去掉日志、功能不变；挂即命中 |
| T22 | 硬编码期望值 | 期望输出与题面示例逐字绑定，换合法实现就挂 | 改一个不影响语义的格式；挂即命中 |
| T23 | 收集失败当通过 | `pytest` 报 collect error，脚本仍写 reward 1 | 制造 import 错误，看 reward |
| T24 | 只测错误路径 | 全是 raises / invalid，没有正常路径 | 写「永远抛异常」的实现；过即命中 |

## rubric 侧（18 条）

| ID | 模式 | 触发信号 | 怎么证明 |
|---|---|---|---|
| R01 | 不可观察 | 「代码优雅」「意图正确」「异常处理完善」无锚点 | 问：标注员实际看到什么？答不出即命中 |
| R02 | 重复计分 | 两条看同一个状态/同一份证据 | 把两条的判据并排；同一份提交能否同时拿分 |
| R03 | 与题面矛盾 | 条目要求题面没要求/明确不要求的行为 | 引题面原文对照 |
| R04 | 与参考解矛盾 | 参考解不满足条目 | 逐条给 `solve.sh` 打分，掉分即命中 |
| R05 | 奖励实现细节 | 「必须用 X 库」「必须几个函数」「必须有注释」 | 构造功能等价、实现不同的解；掉分即命中 |
| R06 | 惩罚合法替代 | 只认一种实现路径 | 同上，换合法实现打分 |
| R07 | 权重算术 | 分值和 ≠ 声称满分；档位换算不闭合 | 把分值相加，对照满分/档位表 |
| R08 | 档位模糊 | 「基本正确」「部分完成」无边界 | 两个标注员独立打分，分差 >10% 即命中 |
| R09 | 缺核心条目 | 题面最核心的能力没有独立条目 | 契约表逐条 R 去 rubric 找，找不到即命中 |
| R10 | 用测试通过率代替能力 | 「测试全过得 N 分」 | 测试本身有漏洞时，坏解也能拿满 |
| R11 | 依赖未提供产物 | 要看覆盖率/性能/trace，但材料里没有 | 检查材料清单；缺即命中 |
| R12 | 同一证据多条目 | 一处代码同时满足三条 | 列证据矩阵，看是否重复 |
| R13 | 风格条目无锚点 | 「命名规范」「结构清晰」没有可检查规则 | 两个标注员打分，分差大即命中 |
| R14 | 分值倒挂 | 次要项分值 > 核心项 | 对照题面核心要求排序 |
| R15 | 奖励拷贝参考解 | 「与参考实现一致得高分」 | 换一个合法实现，看是否掉分 |
| R16 | 评分流程不可执行 | 要求标注员跑测试/改代码/看内部状态 | 检查标注员角色与材料 |
| R17 | 条目覆盖同一维度 | 三条都在看「能不能跑」 | 维度归类，重复即命中 |
| R18 | 忽略题面禁止项 | 题面禁止 X，rubric 不扣 X | 契约表禁止项逐条对照 |

## 高分区的六个信号（优先看）

时间不够时，先查这六处，命中率最高：

1. **`test.sh` 的 reward 写入**：`|| true`、无条件 1、退出码。
2. **取消/中断类测试的副作用断言**：只查状态/异常，不查「停在哪」。
3. **题面每条 MUST 的反向追问**：违反它的实现，哪条测试会挂？
4. **rubric 的权重与参考解**：加起来是不是 100；`solve.sh` 能拿几分。
5. **重复计分**：两条是不是在看同一个可观察量。
6. **题面没定义的边界**：异常类型、返回值、日志、时序。

## 不算缺陷的边界（防止误报）

- 题面明确规定的实现细节（如指定库、指定输出格式）→ 断言它不算过度。
- 测试用 `sleep` 但配了 Event/Barrier 同步 → 不算 flaky。
- rubric 条目比题面更细，但有锚点、参考解能满分 → 不算矛盾。
- 同一行为在两个维度各有一条（如「状态对」与「副作用对」）→ 不算重复。
- 题面没要求、测试也没测 → 不是 `missing_validation`，最多是 `undefined_requirement`。
